# GPCE4 reset-boot web implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Integrate the supplied full-machine core as a usable optional C/Wasm browser mode.
**Architecture:** Independent CPU and SoC C units with one pointer-free machine state. A dedicated Worker runs bounded instruction batches; an isolated browser page reuses existing styling and orientation. Default emulator is unchanged.
**Tech Stack:** C11, Zig 0.15.2, WebAssembly, JavaScript, IndexedDB, Python differential oracle.
**Spec:** ../specs/2026-10-30-gpce4-web-design.md

## Global constraints
- No ROM or user snapshots published. 8MiB firmware, 96KiB local internal ROM.
- Preserve GPL/MAME attribution. No claim of measured physical timing.
- Do not change source `gpce4_machine` or existing emulator snapshot identity.

## Review focus
- Malformed ROM/flash/state and bank/window accesses must fail safely (tasks 1-3).
- IRQ nesting, RETI, register bank and shifts must match reference (task 1).
- Timer boundaries and split batches must preserve state (task 2).
- Restore failure must leave current session and stored saves untouched (task 3).
- Hidden/background tabs pause; page reload restores without offline punishment (task 3).
